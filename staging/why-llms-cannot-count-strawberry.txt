Understanding llm tokens explains why your model hallucinates basic spelling.
It cannot count letters.
It cannot index strings.

An LLM never sees raw text, but rather integer chunks produced by a standalone byte pair encoding tokenizer.

Here is where it bites:
→ Asking an agent to parse fixed-width file columns
→ Paying double API rates for non-Latin localization
→ Unit tests failing on basic character arithmetic

The tokenizer runs before the transformer even wakes up. It matches character sequences against a static dictionary of roughly one hundred thousand common patterns. When you pass strawberry, it splits the word into straw and berry, assigns them IDs, and passes those numbers forward. The individual letters are literally invisible to the attention heads.

This also creates a massive token tax. Common English words get single IDs. Meanwhile, non-Latin scripts get fragmented into single bytes, burning up to ten times more context window and budget for the exact same information density.
