Endianness is the convention a processor uses to arrange the bytes of a multi-byte word in physical memory.

Here is where it bites:
→ Parsing network headers by pointer casting a raw buffer
→ Transferring binary files between x86 servers and legacy mainframes
→ Reading multi-byte integers out of packed hardware telemetry

A 32-bit integer is four bytes long. Big-endian architectures store the most significant byte at the lowest address, mirroring the way Western text reads left to right. Little-endian architectures flip that, storing the least significant byte first so hardware math units can calculate low-order sums while subsequent bytes are still arriving.

The internet standardized on big-endian for wire protocols. Almost every chip running your backend code is little-endian. When you read incoming data straight into memory without swapping, the byte sequence 00 00 00 01 turns into 16,777,216, causing immediate buffer allocations and out-of-memory panics.

Always use standard conversion macros like ntohl or write explicit bitshifts. Don't trust raw pointer casts.
