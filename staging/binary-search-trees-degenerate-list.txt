A binary search tree stores sorted keys where smaller values descend left and larger values branch right.

Here is where it bites:
→ Timestamps stream in already sorted
→ Every incoming value appends strictly to the right branch
→ Logarithmic lookups collapse into linear pointer chasing

When data arrives presorted, naive trees never branch left. The structure degenerates into a single spindly chain across memory. Instead of discarding half the dataset at every level, each search traverses every node sequentially.

On one million items, search cost jumps from twenty comparisons to one million pointer hops. Production runtimes solve this by enforcing self-balancing schemes like Red-Black trees or B-trees, triggering local pointer rotations whenever an insert threatens balance.
