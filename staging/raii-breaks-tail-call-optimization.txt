A clean recursive parser in production.
One lock guard added for thread safety.
Tail call optimization disappears instantly.

Tail call elimination is a compiler transformation where the final function call reuses the current stack frame instead of allocating a fresh activation record.

Picture this:
→ A recursive worker processes millions of incoming events perfectly
→ You declare a lock_guard on line two to protect shared metrics
→ The process crashes with SIGSEGV after blowing the 8MB stack limit

The compiler needs the recursive call to be the very last instruction so it can emit a simple jump. But RAII rules state that non-trivial stack destructors must execute at scope exit.

Because your lock guard destructor runs after the recursive function returns, the recursive call is no longer in the tail position. The compiler is forced to preserve the entire stack frame to wait for that destructor call.

A single forgotten destructor turns an O(1) memory tail call into an O(N) stack explosion.

Remember this next time your clean refactor segfaults in release mode.
