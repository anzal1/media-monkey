Quicksort loses to Insertion Sort on thirty elements.
Big-O notation completely hides why.
Real hardware runs instructions, not asymptotes.

Big-O notation measures how an algorithm scales as input approaches infinity by discarding constant factors and low-order terms.

Picture this:
→ You sort twenty user IDs in a request handler.
→ Your recursive quicksort partitions subproblems and incurs function call overhead.
→ An insertion sort finishes in fewer clock cycles before the stack frame resolves.

Theory discards constants because at scale, n squared eventually outgrows any constant multiplier. But computers do not run at infinity. They run on fixed architectures where branch overhead and function calls add real latency even when data sits cleanly inside cache.

Quicksort demands stack overhead, pivot selection, and extra conditional branches. Insertion Sort runs a compact loop with minimal instruction overhead.

Under roughly sixteen elements, those constant overhead costs dominate the entire runtime.

Respect the crossover point before premature optimization ruins your hot paths.
