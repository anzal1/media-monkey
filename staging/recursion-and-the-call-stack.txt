Understanding recursion and the call stack keeps services alive. 💥

A thread stack is a dedicated chunk of memory reserved to record where code should resume after running a sub-routine.

Here is where it bites:
→ Parsing deeply nested JSON from an untrusted client
→ Traversing an unbalanced binary search tree
→ Trusting tail call optimization in a runtime that disables it

Each function invocation allocates a stack frame to store parameters, local variables, and the return address. That frame must linger in memory until every inner call finishes computing its return value.

Because standard thread stacks are capped around eight megabytes on Linux, deep recursive branches chew through this fixed boundary until the CPU strikes an unmapped guard page. If your runtime does not support tail call elimination, even clean tail-recursive functions will exhaust memory and terminate the process.

Switching to an iterative loop with a heap-backed collection lets your task scale across gigabytes without ever running out of stack space.
