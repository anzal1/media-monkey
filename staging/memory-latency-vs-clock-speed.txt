Engineers tuning memory latency vs clock speed know MHz is a vanity metric.

The memory wall is the silent bottleneck of modern computing: compute speeds advanced exponentially, while memory retrieval speeds stalled.

Here is where it bites:
→ Chasing pointer references across the heap
→ Cache misses forcing a round trip to DRAM
→ Hardware execution units sitting frozen on dependencies

A modern core completes an arithmetic operation in a quarter of a nanosecond. But when code dereferences an unexpected pointer, the processor must leave its ultra-fast local L1 cache and query system DRAM over the bus. That trip takes sixty nanoseconds.

To a four gigahertz processor, sixty nanoseconds feels like hundreds of wasted operational cycles. Even aggressive out-of-order execution queues eventually stall when dependent data fails to arrive. Your code spends most of its runtime doing absolutely nothing.

Structuring your data in contiguous arrays lets the CPU prefetcher pull lines ahead of time, turning random latency stalls into linear stream throughput.
