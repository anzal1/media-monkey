Your H100 compute utilization hovers at four percent during token generation.
Every response trickles back at twenty tokens per second.
You hit the memory bandwidth limit before touching the tensor cores. 🛑

Memory bandwidth is the rate at which your GPU can drag model weights from its off-chip VRAM into on-chip cache.

Here is where it bites:
→ An engineer buys more raw FLOPS expecting instantaneous generation
→ The chip streams a hundred gigabytes of weights across the bus for one token
→ The arithmetic logic units sit completely starved between clock cycles

During prefill, you process whole prompt sequences at once. Matrix multiplication reuses each weight across hundreds of prompt tokens, saturating the tensor cores with high operational intensity.

Decoding breaks that entirely. Every generated token requires an isolated forward pass. To pick the next word from a 70B parameter model in FP16, the GPU must shuffle 140 gigabytes of parameters across the memory bus just to multiply each number once. At 3.35 terabytes per second on an H100, your bus caps your single-user output near twenty-four tokens per second. The cores never get a chance to run hot.

Stop buying compute for generation bottlenecks. You either pack multiple user requests into large continuous batches or quantize weights to eight or four bits to cut byte traffic in half.
