Kenji edits his save file on his computer to give himself 1 coin. When he loads the save onto a network server, his balance explodes into 16,777,216. That silent mismatch is what happens when software clashes over endianness.

Endianness defines the physical byte order used to represent multi-byte words in digital computer memory.

Here is where it bites:
→ Transferring raw binary structures over TCP sockets
→ Sharing save files between x86 desktops and network emulators
→ Parsing binary image and audio headers across CPU architectures

1. Big endian stores the most significant byte at the lowest memory address, mirroring human left-to-right reading.
2. Little endian places the least significant byte at the lowest address so carry math starts instantly in hardware.
3. Network byte order standardizes on big endian for protocols like TCP and IP.
4. Host architectures like x86 and modern ARM run little endian by default.
5. Sockets must invoke conversion routines like ntohl to flip incoming bytes before reading integers.

Forget that conversion and a single packet counter reads 16,777,216 instead of 1.
