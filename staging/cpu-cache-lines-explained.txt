Step by one finishes in five milliseconds.

Hardware always fills cache lines in 64-byte chunks.

Hardware fetches memory in fixed chunks called cache lines, so reading a single integer always pulls its neighbors along for the ride.

Here is where it bites:
→ Traversing a matrix down columns instead of across rows
→ Storing giant structs when your loop only touches one field
→ Splitting hot operational data across chasing linked list pointers

When your instruction pointer asks for a single four-byte integer, the processor core checks its local level one cache. If the bytes are absent, execution stalls while the memory controller fetches data across the bus. But the controller never sends individual variables. It aligns the request to an absolute 64-byte boundary and delivers the entire block.

That block fills a single line in your cache. If your code steps forward sequentially, the next fifteen integers are already sitting four clock cycles away. If your algorithm skips around memory, every single step costs an off-chip round trip while sixty bytes of payload get tossed unused.

Flipping an image processing nested loop from column traversal to row traversal regularly yields an eight to ten times speedup on identical silicon, without changing algorithmic complexity at all.
