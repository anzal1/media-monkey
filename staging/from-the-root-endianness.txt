Sofia copies her save file to a new handheld. Her character had one gold coin, but the balance reads 16,777,216 because an unhandled endianness bug flipped the bytes in memory.

Endianness defines the physical order in which a processor stores multi-byte integers inside memory addresses.

Here is where it bites:
→ Transferring raw binary structures over TCP between different CPU architectures
→ Parsing binary file formats like images, audio headers, or game saves
→ Interpreting hardware sensor registers straight into integer pointers

When Sofia's handheld saves a 32-bit integer representing one, it writes four bytes: 01 00 00 00. That is little-endian format, where the least significant byte sits in the lowest memory address.

If another architecture interprets those identical four memory addresses as big-endian, it reads the byte with value 1 as the most significant place value. Instead of 2 to the power of 0, that byte is evaluated as 2 to the power of 24, giving 16,777,216.

A single forgotten conversion flips a basic counter into tens of millions or drops a high score straight to zero.
