A prefix tree, or trie, is an ordered tree data structure where keys are usually strings, and every descendant of a node shares a common prefix.

Picture this:
→ A user types three letters into an empty autocomplete input.
→ A relational query runs an expensive scan across six-figure row sets.
→ A memory-bound engine hops three pointers and isolates the exact subtree.

Instead of comparing whole words against each other, the trie splits words into individual characters along edges. Common prefixes share the exact same structural path down from the root, meaning matching terms automatically cluster together.

Once your traversal reaches the end of the input query, every leaf node inside that downstream subtree represents an authorized completion. The complexity of resolving that prefix depends strictly on the count of characters typed, not the scale of your collection.

Naively allocating pointers per character inflates memory usage up to fifteen times over raw text size and triggers constant cache misses. Real production engines collapse these paths with radix trees to fit entirely within L3 cache.
