Understanding prefill vs decode explains why your server stalled.

Large language model inference is split into two fundamentally different hardware regimes with opposing bottlenecks.

Here is where it bites:
→ Prompt processing pegs every tensor core at full saturation
→ Token generation leaves raw compute cores idling at low utilization
→ Memory bandwidth completely suffocates your streaming generation

During prefill, the model processes the entire prompt at once. Every token is already known, so the GPU runs massive matrix multiplications across all tokens simultaneously. The arithmetic intensity is huge. You are compute bound: your speed is limited only by how fast your tensor cores can crunch floating-point math.

Decode is the exact opposite. Because language generation is autoregressive, each new token depends on the previous one. To generate a single output word, the GPU must fetch tens of gigabytes of model weights from high-bandwidth memory into on-chip cache just to do a tiny vector-matrix multiply. You are memory bound, spending nearly all execution time waiting on memory busses.

This is why modern inference engines disaggregate prefill and decode onto different machines or rely on continuous batching to bundle hundreds of decode streams into a single memory pass.
