A boolean takes one byte.
A double takes eight.
Ignoring struct layout and padding inflates them both to twenty-four.

Hardware buses fetch memory on naturally aligned word boundaries, forcing compilers to insert silent padding bytes whenever field offsets do not match alignment requirements.

Here is where it bites:
→ A struct with alternating small and large fields nearly doubles in size
→ Tight array iterations pull empty padding bytes across system memory buses
→ Hot L1 cache lines fill up with unread padding and evict working sets early

Modern processor cores read system memory in sixty-four-byte cache lines. When you declare an eight-byte integer right after a one-byte flag, the compiler cannot place that integer on offset one without causing costly unaligned memory access penalties. It quietly inserts seven unused padding bytes to align the integer to an eight-byte boundary.

At the end of the struct, trailing padding rounds the entire allocation up to a multiple of its largest member so that array indexing preserves alignment. In dense collections, this dead space cuts your effective cache bandwidth in half.

Sort your struct fields in descending order of size. Placing pointers and eight-byte primitives first eliminates internal holes automatically, squeezing twice as many records into every single cache line.
